a) Adatbázisrendszerek II — PL/SQL alapok

A PL/SQL program felépítése 4. Blokkok és alprogramok 5. Tárolt eljárások, tárolt függvények összehasonlítása, csomagok készítésének célja és lehetőségei 6. PL/SQL alapok

PL/SQL (Procedural Language for SQL): az Oracle eljárás-szerű kiterjesztése az SQL-hez. SQL-utasítások procedurális kódba ágyazhatók — változókkal, vezérlési szerkezetekkel, kivételkezeléssel.

Típusok

Skalár típusok: - Numerikus: NUMBER(p, s), INTEGER, BINARY_INTEGER, PLS_INTEGER, FLOAT - Karakteres: CHAR(n), VARCHAR2(n), LONG, CLOB - Dátum: DATE, TIMESTAMP - Logikai: BOOLEAN (csak PL/SQL-ben, nem SQL-ben!) - Bináris: RAW, BLOB

Összetett típusok: - %TYPE: átvesz egy tábla-oszlop típusát - nev Diakok.nev%TYPE; - %ROWTYPE: átvesz egy egész tábla sortípusát (rekord) - diak Diakok%ROWTYPE; - RECORD: saját rekord - TABLE: asszociatív tömb - VARRAY, NESTED TABLE: kollekciók

Változók és konstansok

DECLARE
    nev VARCHAR2(50) := 'Anna';
    eletkor NUMBER(3) NOT NULL := 25;
    pi CONSTANT NUMBER := 3.14159;
BEGIN
    DBMS_OUTPUT.PUT_LINE(nev);
END;
  • Deklaráció: név típus [:= kezdőérték];
  • CONSTANT: futás közben nem módosítható
  • NOT NULL: kötelező kezdőérték

Vezérlési szerkezetek

Szelekció:

IF feltétel THEN ...
ELSIF feltétel THEN ...
ELSE ...
END IF;

CASE érték
    WHEN 1 THEN ...
    WHEN 2 THEN ...
    ELSE ...
END CASE;

Ciklusok:

LOOP
    ...
    EXIT WHEN feltétel;
END LOOP;

WHILE feltétel LOOP
    ...
END LOOP;

FOR i IN 1..10 LOOP
    ...
END LOOP;

FOR rec IN (SELECT id, nev FROM Diakok) LOOP
    DBMS_OUTPUT.PUT_LINE(rec.nev);
END LOOP;

SQL utasítások a PL/SQL-ben

DML utasítások (SELECT, INSERT, UPDATE, DELETE) közvetlenül beágyazhatók.

SELECT nev INTO v_nev FROM Diakok WHERE id = 1;

UPDATE Diakok SET szul_ev = 2001 WHERE id = 1;

INSERT INTO Diakok VALUES (1, 'Béla', 2000);

DELETE FROM Diakok WHERE id = 1;

SELECT … INTO: egy sort kérdez le egy változóba. Ha nincs találat → NO_DATA_FOUND, ha több → TOO_MANY_ROWS kivétel.

DDL utasítások (CREATE, DROP, ALTER) csak EXECUTE IMMEDIATE-tel:

EXECUTE IMMEDIATE 'CREATE TABLE tmp (id NUMBER)';

PL/SQL program felépítése — blokk

Anonim blokk:

DECLARE
    -- deklarációk
BEGIN
    -- végrehajtható rész
EXCEPTION
    -- kivételkezelés
END;

A blokk 3 része: 1. DECLARE — változók, típusok, kurzorok 2. BEGIN … END — végrehajtandó utasítások (kötelező) 3. EXCEPTION — kivételkezelés (opcionális)

Blokkok egymásba ágyazhatók.

Alprogramok — eljárások és függvények

Tárolt eljárás (PROCEDURE): nem ad vissza értéket (vagy OUT paraméteren keresztül).

CREATE OR REPLACE PROCEDURE diak_torles(p_id IN NUMBER) IS
BEGIN
    DELETE FROM Diakok WHERE id = p_id;
    COMMIT;
END;

Tárolt függvény (FUNCTION): mindig RETURN értékkel.

CREATE OR REPLACE FUNCTION diak_szam RETURN NUMBER IS
    v_szam NUMBER;
BEGIN
    SELECT COUNT(*) INTO v_szam FROM Diakok;
    RETURN v_szam;
END;

Eljárás vs függvény

Procedure Function
Visszatérés Nincs (vagy OUT-on) Kötelező RETURN
Hívás Önálló utasításként Kifejezésben (SELECT, IF stb.)
SQL-ben Nem hívható közvetlenül Hívható SELECT-ben

Csomagok (PACKAGE)

Csomag: logikailag összetartozó eljárások, függvények, típusok, kurzorok csoportja. Két részből áll:

Specifikáció (interface): mit lehet kívülről hívni.

CREATE OR REPLACE PACKAGE diak_pkg IS
    PROCEDURE diak_torles(p_id IN NUMBER);
    FUNCTION diak_szam RETURN NUMBER;
END diak_pkg;

Body (implementáció): hogyan van megvalósítva.

CREATE OR REPLACE PACKAGE BODY diak_pkg IS
    PROCEDURE diak_torles(p_id IN NUMBER) IS ...
    FUNCTION diak_szam RETURN NUMBER IS ...
END diak_pkg;

Előnyök: - Encapsulation — csak a specifikációban deklaráltak láthatók kívülről - Modularitás — összetartozó dolgok egy helyen - Teljesítmény — első hívásnál egészében memóriába kerül - Globális állapot — csomag-szintű változók

Paraméterezési lehetőségek

3 mód:

  • IN (alapeset): bemeneti, csak olvasható az alprogramban
  • OUT: kimeneti, az alprogram adja vissza rajta. Híváskor null-ozódik. Csak változónak adható.
  • IN OUT: be- és kimenet — bemenetnek is, és az alprogram is módosíthatja
PROCEDURE p(
    a IN NUMBER,
    b OUT NUMBER,
    c IN OUT VARCHAR2
) IS BEGIN ... END;

Paraméter-átadás módjai: - By value (IN alapeset): érték másolat - By reference (IN OUT): referencia - OUT: átadáskor érték nincs használva, csak visszamenetben

Hívás: - Pozicionális: p(1, x, y) - Megnevezett: p(a => 1, b => x, c => y) - Vegyesen is lehet (előbb a pozicionális)

Kivételek kezelése

PL/SQL-ben a hiba kivételként jelenik meg, és az EXCEPTION blokkban kezelhető.

BEGIN
    SELECT nev INTO v_nev FROM Diakok WHERE id = 999;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('Nincs ilyen diák');
    WHEN OTHERS THEN
        DBMS_OUTPUT.PUT_LINE('Egyéb hiba: ' || SQLERRM);
END;

Beépített kivételek: - NO_DATA_FOUND — SELECT INTO nem talált - TOO_MANY_ROWS — SELECT INTO több sort kapott - INVALID_CURSOR — kurzor érvénytelen - ZERO_DIVIDE — nullával osztás - VALUE_ERROR — típusátalakítási hiba - OTHERS — minden más

Saját kivétel:

DECLARE
    sajat_hiba EXCEPTION;
BEGIN
    IF rossz_feltetel THEN
        RAISE sajat_hiba;
    END IF;
EXCEPTION
    WHEN sajat_hiba THEN ...
END;

RAISE_APPLICATION_ERROR: alkalmazás-specifikus hibakód+üzenet dobása (-20000 -től -20999-ig).

Raszteres algoritmusok

Cél: folytonos geometriai alakzatokat képpontokkal közelíteni. DDA (Digital Differential Analyzer) algoritmusok adnak választ.

DDA szakaszrajzoló

Az egyenes y = mx + b egyenletéből indul. m = dy/dx-ből meghatározzuk a növekményeket, és minden lépésben az x-et eggyel, az y-t m-mel növeljük.

Hátrány: lebegőpontos műveletek, az (x, y) értékeket kerekíteni kell → nem ideális kép.

MidPoint szakasz

Csak egész számokkal dolgozik. Tegyük fel, 0 ≤ m ≤ 1, balról jobbra rajzolunk.

Adott a jelenleg megrajzolt pont P(xₚ, yₚ). A következő E (East) vagy NE (NorthEast) lehet. A felezőpont (M) és az elméleti egyenes viszonya alapján döntünk. Csak inkrementális egész számításokkal.

MidPoint kör

Origó középpontú r sugarú kör: x² + y² = r².

Nyolcas szimmetria: ha (x, y) a körön van, akkor a másik 7 pont is a kör része (mindenféle előjel- és koordináta-csere). Elég egy nyolcadot kiszámolni.

Az aktuális P(xₚ, yₚ) után E vagy SE lesz a következő pont, a felezőpont M alapján.

Ha a középpont nem az origó → koordináta-eltolás.

Cohen-Sutherland vágó (clipping)

A síkot 9 részre osztjuk; a középső a képernyő. Minden részhez 4 bites kódot rendelünk: - 1. bit: 1, ha a pont a felső vonal felett - 2. bit: 1, ha az alsó vonal alatt - 3. bit: 1, ha a jobb oldali vonaltól jobbra - 4. bit: 1, ha a bal oldali vonaltól balra

Algoritmus: - Ha mindkét végpont kódja 0000 → szakasz teljesen belül - Ha a két kód AND-je nem 0 → mindkét végpont ugyanazon az oldalon kívül → szakasz kívül esik - Egyébként: egyik végpontot eltoljuk a megfelelő képernyő-éllel való metszéspontra, és újra ellenőrizzük

Előny: hatékony, 3D-re általánosítható (6 bittel). Hátrány: csak téglalap ablakra működik, poligonra nem.

Paraméteres görbék

A síkon mozgó pont r(t) vektor egy görbét ír le. - Síkon: r(t) = (x(t), y(t)) - Térben: r(t) = (x(t), y(t), z(t))

Megjelenítés: [a, b]-t felosztjuk, kiszámítjuk a pontokat, és törött vonallal kötjük össze.

Hermite-ív (interpoláció)

Két végpont (p₀, p₁) + két érintővektor (t₀, t₁) → harmadfokú polinomot keresünk:

s(u) = a₃u³ + a₂u² + a₁u + a₀, u ∈ [0, 1]

Feltételek: s(0) = p₀, s(1) = p₁, s'(0) = t₀, s'(1) = t₁.

A 4 egyenletből Hermite-polinomokat kapunk: - H₀³(u) = 2u³ - 3u² + 1 - H₁³(u) = -2u³ + 3u² - H₂³(u) = u³ - 2u² + u - H₃³(u) = u³ - u²

s(u) = p₀·H₀³ + p₁·H₁³ + t₀·H₂³ + t₁·H₃³

Hátrányok: érintőkkel definiálni körülményes, hurok keletkezhet, görbe metszheti önmagát.

Bézier görbe (approximáció)

Approximáció: a görbe a kontrollpontokat közelíti, nem feltétlenül halad át rajtuk (csak az első és az utolsón).

Bernstein-polinom: Bᵢⁿ(u) = (n choose i) · uⁱ · (1-u)ⁿ⁻ⁱ

s(u) = Σᵢ bᵢ · Bᵢⁿ(u), u ∈ [0, 1]

Tulajdonságok: - Végpontok interpolációja - Konvex burok-tulajdonság: a görbe a kontrollpontok konvex burkán belül marad - Affin transzformációkkal szemben invariáns (kontrollpontokat transzformáld, a görbét újraszámolod) - Globális változtathatóság: egy kontrollpont mozgatása az egész görbét befolyásolja - Konvex poligon → konvex görbe; konkáv poligon is generálhat konvex görbét

Hátrány: magas fokszámnál merev, nem követi a poligont jól → alacsony fokú görbéket csatlakoztatunk.

B-Spline

Bázisfüggvények (4 kontrollpontos esetben): - N₀(t) = (1-t)³/6 - N₁(t) = (t³/2) - t² + 2/3 - N₂(t) = (t³/2) + (t²/2) + (t/2) + 1/6 - N₃(t) = t³/6

Tulajdonságok: - Görbeívek automatikusan csatlakoznak, megfelelő folytonossággal - Nem látszanak a csatlakozási pontok - A görbe nem érinti a végpontokat - Új kontrollpont lokálisan hat (csak közvetlen környezetét módosítja) — szemben a Bézier-rel

Homogén koordináták

A 3D-s pontot 4 koordinátával reprezentáljuk (arányosság erejéig): - (x, y, z, w), ahol w ≠ 0 - Két homogén koord. ugyanazt a pontot jelöli, ha az egyik a másik konstansszorosa - (0, 0, 0, 0) nem létezik

Áttérés: Descartes (x, y, z) → homogén (x, y, z, 1). Visszatérés: (x, y, z, w) → (x/w, y/w, z/w) ha w ≠ 0.

Cél: az eltolás is mátrix-szorzással leírható lesz (Descartesben nem volt). Térben 4×4 mátrixokkal.

Pont-transzformációk

Geometriai transzformációk: a tér minden p pontjához egyértelműen rendelnek egy p' pontot. Térben 4×4 mátrixokkal írjuk le, a pontok homogén koordinátákkal.

A p pont transzformáltját p' = M · p adja.

Műveletek: - Eltolás (translation): p' = p + v - Forgatás (rotation): α szöggel, tengely körül. Tetszőleges tengely → 3 koordináta-tengely körüli forgatás kompozíciója - Tükrözés (reflection): koordinátasíkra. A nem szereplő tengelyhez tartozó koord. negálása - Origó középpontú nyújtás-zsugorítás (scaling): minden tengely irányában azonos mértékkel - Skálázás: különböző arányban a tengelyek mentén - Nyírás (shear): adott síkkal párhuzamos csúsztatás

Window-Viewport transzformáció: képsík ablak → képernyő ablak. Eltolás origóba → skálázás → eltolás a végleges pozícióba.

Tér leképezése síkra — vetítések

Vetítés: R³ → R² leképezés.

Párhuzamos vetítés: a p pontot egy v irányvektor mentén eltoljuk, míg el nem éri a képsíkot. - Megtartja: egyenes, párhuzamosság, arányok - Nem tartja meg: távolság, szög

Centrális (perspektív) vetítés: vetítés centrumát (kamera) és a képsíkot kell megadni. Realisztikusabb — közelibb objektum nagyobb. Párhuzamos szelők tétele alkalmazható.

Axonometria: adott a térbeli koordináta-rendszer (origó + e₁, e₂, e₃) és ezek képei (origó' + e₁', e₂', e₃'). A térbeli p pont képét úgy kapjuk meg, hogy a koordinátáit megszorozzuk a hozzájuk tartozó egységvektorok képeivel és összegezzük.

Poliéderek

Színes, árnyalt megjelenítéshez a felületeket poligon hálóval közelítjük. Általában háromszögek (3 pont mindig egy síkban).

Wire Frame modell

Drótvázmodell — csak a csúcsokat és az éleket tárolja. Egyszerű, de: - A kép sokszor értelmezhetetlen - Nem lehet eltávolítani a nem látható részeket

B-Rep (Boundary Representation)

A Wire Frame továbbfejlesztése. Tárolja: - Geometriai info: csúcspontok koord., élek és lapok egyenlete - Topológiai info: lapok, élek, csúcspontok kapcsolatai

Élek és háromszögek tárolása csúcsokra mutatókkal.

Poliéderek megjelenítése — hátsó lapok eltávolítása

Zárt poliédereknél a háttér felé néző lapok nem látszanak. Lépések: 1. Lap normálvektorának kiszámítása (vektoriális szorzat) 2. A lapból a kamerába mutató vektor és a normál közötti szög (skaláris szorzat) — ha 90°-nál nagyobb, akkor a lap nem látszik, eltávolítható

Rendezés átfedés-kezeléshez: a háromszögeket a súlypont z koordinátája szerint rendezzük (módosított gyorsrendezés) — hátulról kezdjük megjeleníteni, az elülsők kitakarják a hátsókat.

Z-Buffer algoritmus

Pixelenként vizsgálja, melyik objektum látszik ott. Minden pixelhez: - Mélységérték (Z) — kezdetben végtelen / max - Szín

Algoritmus: 1. Inicializálás: minden pixel Z = max, szín = háttér 2. Bejárjuk az objektumokat, azokon belül a vetület pixeleit 3. Ha a pixelhez tartozó pont z koord. közelebb van, mint a tárolt érték → kicseréljük (új szín, új Z)

Egyszerű, gyors, párhuzamosítható. Hardver támogatott.

Árnyalási technikák

Flat (konstans) árnyalás: - Minden lap egy pontjában kiszámítjuk a színt → azt használjuk az egész lapra - Akkor ideális, ha a fény párhuzamos, a kamera végtelenben, a felület poliéder - Görbült felületek poliéder-közelítésénél: ugrásszerű színváltások a szomszédos lapok közt

Gouraud árnyalás: - Minden csúcsban kiszámítjuk a színt a normálisok alapján - Lap élein: lineáris interpoláció - Belső pontokban: kettős lineáris interpoláció - Hátrányok: körvonal nem sima (látszik a poligon), nagy tükröződésnél ugrás

Phong árnyalás: - A csúcsokban tárolt normálisokat interpolálja (nem a színeket!) - Minden belső pontban kiszámolja a normált, majd a színt - Több számítás, de szebb eredmény - Sima tükröződés, görbült érzet még poliéderből is
