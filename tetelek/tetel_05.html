a) Magasszintű programozási nyelvek II — OOP alapok

Hivatalos kérdés: 1. Az OOP alapelvei, alapfogalmai 2. Mezők, metódusok, property-k, adatrejtés 3. Konténerosztályok használata és indexelők 4. Osztályszint és példányszint 5. Névterek 6. Bővítő metódusok 7. Operator overloading

OOP alapelvei

A négy klasszikus alapelv:

  1. Egységbe zárás (encapsulation): az adat és a rajta értelmezett műveletek egy egységben (osztályban) vannak; az adat adatrejtéssel védett.

  2. Adatrejtés (information hiding): az osztály belső állapota kívülről nem közvetlenül elérhető — private mezők, csak public metódusokon / property-ken keresztül.

  3. Öröklődés (inheritance): új osztály egy meglévő osztály képességeit örökli + bővíti.

  4. Többalakúság (polymorphism): ugyanaz a metódus-név más-más viselkedést jelent a típustól függően (override-olás, virtual).

Alapfogalmak

  • Osztály (class): sablon — definiálja, milyen adatai és metódusai vannak az objektumoknak.
  • Objektum (példány): osztály egy konkrét megvalósulása.
  • Konstruktor: speciális metódus, ami létrehozáskor fut le.
  • Destruktor / finalizer: felszabadításkor (C#-ban a GC kezeli).

Mezők

A mező (field) az osztály adat-tartalma: - private (alapeset C#-ban): csak az osztályon belül látható - public: bárhonnan - protected: az osztály + leszármazottak - internal: ugyanazon assembly-n belül - static: osztályszint (lásd lent) - readonly: csak konstruktorban kaphat értéket

Metódusok

Az osztály viselkedése. Szignatúra: név + paraméterlista. Visszatérési típussal. Lehet static vagy példányszintű.

Túlterhelés (overload): azonos név, más paramétertípus.

Property-k

C# specifikus konstrukció — getter/setter elegáns szintaxisa. Kívülről úgy viselkedik, mint egy mező, de metódushívás alatta.

public int Eletkor {
    get { return eletkor; }
    set {
        if (value >= 0) eletkor = value;
    }
}

// Auto-property
public string Nev { get; set; }
public string Id { get; init; }  // C# 9+, csak konstruktorban

Adatrejtés

A private mezőket csak public property-ken vagy metódusokon keresztül érjük el → a belső állapot védett, módosításnál érvényesíthetjük az invariánsokat (pl. életkor nem lehet negatív).

Konténerosztályok használata

A System.Collections.Generic névtér tartalmazza: - List<T> — dinamikus tömb - Dictionary<K, V> — hash-tábla - HashSet<T> — halmaz - Stack<T>, Queue<T> — verem, sor - LinkedList<T> — láncolt lista - SortedSet<T>, SortedDictionary<K, V> — rendezett (fa-alapú)

Mind generikusak — típusbiztos, boxing nélküli.

Indexelők

C# specifikus — az osztály objektumai indexelhetők, mint egy tömb.

class Tarolo {
    private string[] items = new string[10];
    public string this[int i] {
        get { return items[i]; }
        set { items[i] = value; }
    }
}

Tarolo t = new();
t[3] = "alma";   // indexelő hívása

Osztályszint és példányszint

Példányszintű (instance): az objektumhoz tartozik. Példányonként külön értéke van.

Osztályszintű (static): - Az osztályhoz tartozik, nem példányhoz - Egyetlen közös példánya van az alkalmazásban - Példányosítás nélkül elérhető (Math.Sqrt(2)) - Osztályszintű konstruktor (static constructor): egyszer fut le, az osztály első használatakor

Névterek (namespace)

Csoportosítja az összetartozó típusokat, névütközéseket kerüli el.

namespace MyApp.Models {
    public class Felhasznalo { ... }
}

// Használat:
using MyApp.Models;
var u = new Felhasznalo();

// Vagy teljes minősítéssel:
var u = new MyApp.Models.Felhasznalo();

A BCL is névterekbe szervezett: System, System.IO, System.Collections.Generic, System.Linq stb.

Bővítő metódusok (extension methods)

Lehetővé teszi, hogy meglévő típushoz új metódust adjunk, anélkül, hogy módosítanánk az eredetit. static metódus statikus osztályban, első paraméter elé this.

public static class StringExtensions {
    public static bool IsEmail(this string s) {
        return s.Contains("@");
    }
}

// Használat — úgy néz ki, mintha a string osztály metódusa lenne
"foo@bar.com".IsEmail();

A LINQ teljes egészében bővítő metódusokra épül.

Operator overloading

Lehetővé teszi, hogy saját operátorokat definiáljunk osztályokhoz.

public static Vector operator +(Vector a, Vector b) {
    return new Vector(a.X + b.X, a.Y + b.Y);
}

Megkötések: - Csak static lehet - Az == és !=, < és > párban definiálandók - Bizonyos operátorok nem overload-olhatók (pl. &&, ||, =) - Ha ==-t definiálsz, az Equals és GetHashCode is felülbírálandó

Cache használata

Cache (gyorsítótár): kis méretű, gyors átmeneti tároló — a CPU és a lassabb fő memória között. Cél: csökkenti az átlagos memória-elérési időt.

A gyorsítótár vezérlője bemásolja a kért adatot a cache-be — a következő hozzáférés gyors.

  • Cache hit: a kért adat benne van a cache-ben
  • Cache miss: nincs benne — meg kell várni a lassabb memóriát

Hatékonyság: átlagos elérési idő = hit_rate × cache_idő + miss_rate × memória_idő.

Lokalitási elvek

A cache hatékonyságának alapja, hogy a CPU hajlamos ugyanazokat a memóriaterületeket többször felhasználni.

  • Időbeli lokalitás (temporal): ha egy adatot most használtam, valószínűleg újra fogom használni hamarosan (pl. ciklusváltozók).
  • Térbeli lokalitás (spatial): ha egy memóriaterületet érintek, a környezetét is valószínűleg érinteni fogom (pl. tömb-bejárás).

A cache adatblokkokat (cache line) húz be — kihasználja a térbeli lokalitást.

Memória hierarchia

Szint Méret Sebesség Hozzáférés
CPU regiszterek ~bájt ~1 ciklus Közvetlen
L1 cache ~32-64 KB ~3-5 ciklus CPU-mag
L2 cache ~256 KB – 1 MB ~10-20 ciklus CPU-mag (vagy közös)
L3 cache ~4-32 MB ~30-50 ciklus Magok közös
Operatív memória (RAM) ~GB ~100-200 ciklus DRAM
SSD/HDD ~TB ~milliszekundum Háttértár

Cache helye: a CPU és a RAM között. L1 a leggyorsabb, legkisebb; L3 a leglassabb cache de a leggyorsabb RAM-nál.

Cache felépítése

A cache sorokra (cache line) van osztva. Egy sor tartalma: - Címtár (tag): az adatblokk eredeti memóriabeli helyét azonosítja - Adatblokk: 2ⁿ bájt egybefüggő memóriaterület (jellemzően 64 bájt) - Valid bit és dirty bit

Elérési változatok

1. Direkt leképezésű (direct mapped): - Minden memóriablokk pontosan egy cache-sorba kerülhet - A cím index részéből számoljuk - Gyors, egyszerű — de ütközés gyakori, ha két használt blokk ugyanoda esne

2. Asszociatív (fully associative): - Bármely memóriablokk bármelyik cache-sorba kerülhet - Minden sort párhuzamosan kell ellenőrizni → drága - Nincs ütközés

3. Halmaz-asszociatív (n-way set associative): - Köztes megoldás — a cache halmazokra (set) osztva, minden halmazban n cache-sor - Egy memóriablokk n lehetséges helyre kerülhet - Gyakorlatban: 2-, 4-, 8-way

Címbitek számának meghatározása

A memóriacímet 3 részre bontjuk: - Tag (címtár): azonosítja a blokkot - Index (set): melyik halmaz / sor - Offset (eltolás): a blokkon belüli bájt-pozíció

Ha az adatblokk 2^b bájt, az index 2^i sor (vagy set), és a cím n bites: - Offset bitek = b - Index bitek = i - Tag bitek = n − i − b

Direkt leképezés esetén az index közvetlenül a sor sorszáma. n-way esetén a set indexe; a tag azt mondja meg, melyik sor a setben.

Visszaírási módok

Write-through: a CPU által módosított adatot azonnal kiírja a memóriába (és a cache-be is). - Egyszerű, mindig konzisztens - Lassú (minden írás memóriát ér)

Write-back: a módosítás csak a cache-be megy. A dirty bitet 1-re állítja. A cache sor törlésekor (kiváltáskor) írja vissza a memóriába. - Gyors - Bonyolultabb (konzisztencia kezelés szükséges, főleg multiprocesszoros)

Dirty és valid flag-ek

Valid bit (1 bit): érvényes-e az adott cache sor adata? - Bekapcsoláskor 0 - Adat betöltésekor 1-re vált - Sor felszabadításakor 0-ra (több algoritmus van, pl. LRU = legrégebben használt)

Dirty bit (1 bit): a CPU módosította-e a cache sor adatát? - Ha nem módosítottuk → 0 (visszaírás nem szükséges) - Ha módosítottuk → 1 (a sor törlésekor vissza kell írni) - Sor érvénytelenítése előtt: ha dirty=1 → write-back a memóriába

✚ Pótlás: I/O és tipikus perifériák

Input/Output (I/O): a CPU és a külvilág (perifériák) közötti adatcsere.

I/O alapmódok: - Programmed I/O (polling): a CPU rendszeresen lekérdezi a periféria állapotát. Egyszerű, de CPU-pazarló. - Megszakítás (interrupt) vezérelt: a periféria szól, ha kész — a CPU mást csinálhat addig. - DMA (Direct Memory Access): dedikált vezérlő közvetlenül a memória és a periféria között mozgat adatot, a CPU csak indítja és értesítést kap a végén. Nagy adatmennyiséghez ideális.

Címzési módok: - Port I/O: külön I/O címtér, dedikált utasítások (Intel IN, OUT) - Memóriába képezett I/O (MMIO): a periféria a memóriacímtér része — normál load/store utasítások használhatók

PC perifériák

  • Beviteli: billentyűzet (USB), egér, szkenner, mikrofon, webkamera, érintőképernyő
  • Kiviteli: monitor (HDMI, DisplayPort, VGA), nyomtató (USB, hálózat), hangszóró
  • Tárolás: HDD (SATA), SSD (NVMe, SATA), USB drive, optikai meghajtó (egyre ritkább)
  • Hálózati: Ethernet (RJ45), Wi-Fi, Bluetooth
  • Buszok: USB (1.1/2/3/4/USB-C), PCI Express (bővítőkártyák), SATA

Mobil perifériák

A mobil eszközök erősen integráltak — a perifériák a SoC (System on Chip) köré épülnek.

  • Beviteli: érintőképernyő (kapacitív multitouch), gomb, mikrofon
  • Szenzorok (jellegzetesen mobil):
  • Gyorsulásmérő (accelerometer) — eszköz mozgása, képernyő-orientáció
  • Giroszkóp (gyroscope) — forgási sebesség
  • Magnetométer — irány (iránytű)
  • GPS — helymeghatározás
  • Közelség-érzékelő (proximity) — pl. fülhöz emelt telefon képernyőjének kikapcsolása
  • Fény-érzékelő — automatikus fényerő
  • Ujjlenyomat-olvasó, arcfelismerés
  • Kiviteli: képernyő (OLED, LCD), hangszóró, rezgő motor
  • Kapcsolódás: Bluetooth, Wi-Fi, mobilhálózat (4G/5G), NFC (érintéses fizetés)
  • Kamera(k): fő- és előlapi, mélységérzékelés (ToF, LiDAR)

Robotikai környezet perifériái

A robotok szenzor-aktuátor alapúak — bemenetek a környezetről, kimenetek mozgásra.

Szenzorok (bemenet): - LIDAR — lézeres távolságmérés, 360°-os térképezés - Ultrahangos (sonar) — közeli akadály-detektálás - IR (infravörös) szenzorok — vonalkövetés, közelség - Kamera + computer vision — objektum-felismerés, vizuális SLAM - IMU (Inertial Measurement Unit): accelerometer + giroszkóp + magnetométer együtt - Erő- / nyomás-érzékelők — érintés, robotkéz - Enkóderek — motor pozíció / fordulatszám - GPS — kültéri pozícionálás

Aktuátorok (kimenet): - DC motorok, léptetőmotorok, szervomotorok - Lineáris aktuátorok - Mágnesszelepek, pneumatika

Vezérlő interfészek: - GPIO (General Purpose Input/Output) — digitális ki/be (Raspberry Pi, Arduino) - PWM (Pulse Width Modulation) — motorvezérlés, szervó pozícionálás - I²C, SPI, UART — soros kommunikáció szenzorokkal, MCU-kkal - CAN bus — autóipari, ipari robotika - EtherCAT, PROFINET — ipari hálózat

Robotikai stack: szenzorfúzió → percepció → tervezés (path planning) → vezérlés → aktuátorok.
