7. tétel — OOP öröklődés · Adatbázisok I (SQL)

a) Magasszintű programozási nyelvek II — Öröklődés

Hivatalos kérdés: 1. Öröklődés 2. Korai kötés, késői kötés 3. Konstruktorok, konstruktorhívási lánc, osztályszintű konstruktor 4. Típuskompatibilitás, object osztály 5. Dinamikus és statikus osztályok

Öröklődés

Új osztály egy meglévő osztály képességeit örökli, kibővítheti, módosíthatja.

Szintaxis (C#):

class Allat {
    public string Nev { get; set; }
    public virtual void Hangot() { Console.WriteLine("..."); }
}

class Kutya : Allat {
    public override void Hangot() { Console.WriteLine("Vau!"); }
}
  • : jellel jelöljük az ős-osztályt
  • C#-ban egyszeres öröklődés osztályoknál; többszörös csak interface-eknél
  • Az ős védett és public tagjait örökli a gyerek; a private-okat nem közvetlenül
  • A sealed kulcsszóval megtilthatjuk az öröklődést

Korai és késői kötés

Korai kötés (static / early binding): a metódushívást fordításkor dönti el a fordító — a változó deklarált típusa alapján.

Késői kötés (dynamic / late binding): a metódushívást futásidőben dönti el — az objektum tényleges típusa alapján.

C#-ban: - Alapból korai kötés - virtual + override kombóval → késői kötés - A virtual metódusokhoz az osztály egy DMT (Dinamikus Metódus Tábla, vtable)-t épít, ami az ősosztály felé mutat - A hívás a DMT-ből oldódik fel — ezért működik a polimorfizmus

Allat a = new Kutya();
a.Hangot();  // -> "Vau!" (késői kötés, mert virtual + override)

new módosító: ha a gyerek metódus elrejti az ős metódusát kötéssel (new jelzéssel), nincs polimorfizmus — a deklarált típus dönt.

Konstruktorok

A konstruktor egy speciális metódus, amely az objektum létrehozásakor fut le. Inicializálja az állapotot.

  • Neve megegyezik az osztály nevével
  • Nincs visszatérési típusa
  • Lehet több (overload-olt) konstruktor
  • Ha nem írunk → alapértelmezett (paraméter nélküli) konstruktor készül
class Pont {
    public int X, Y;
    public Pont(int x, int y) { X = x; Y = y; }
    public Pont() : this(0, 0) {}  // ugyanezen osztály másik konstruktorát hívja
}

Konstruktorhívási lánc

Származtatott osztály létrehozásakor mindig lefut az ős-konstruktor is, az osztály hierarchia mentén az ős felől lefelé.

class Allat {
    public Allat() { Console.WriteLine("Allat()"); }
}
class Kutya : Allat {
    public Kutya() { Console.WriteLine("Kutya()"); }
}

new Kutya();  // -> "Allat()" majd "Kutya()"

A : base(args) szintaxissal explicit ős-konstruktort hívhatunk:

class Kutya : Allat {
    public Kutya(string nev) : base() { ... }
}

Osztályszintű (static) konstruktor

Lefut egyszer, automatikusan, az osztály első használata előtt. Inicializálja a static mezőket.

class Logger {
    public static string FileName;
    static Logger() {
        FileName = "default.log";
    }
}
  • Paraméter nélküli
  • Nem hívható manuálisan
  • Pontos lefutási idejét a runtime határozza meg

Típuskompatibilitás, object osztály

Felfelé castolás (upcasting): a leszármazott típusú objektum hozzárendelhető egy ősosztály típusú változóhoz. Implicit, mindig biztonságos.

Kutya k = new Kutya();
Allat a = k;  // implicit upcast

Lefelé castolás (downcasting): ősből gyerekbe — explicit kell, és kockázatos (futásidejű kivétel, ha tényleg nem az a típus).

Allat a = new Kutya();
Kutya k = (Kutya)a;  // explicit cast, működik
Kutya k = a as Kutya;  // null, ha nem Kutya
if (a is Kutya k) { ... }  // type pattern (C# 7+)

object osztály: C#-ban minden osztály végül az object-ből származik. Tehát bármi értékét el lehet helyezni object típusú változóban.

Az object metódusai (örökölhetők/felülbírálhatók): - ToString() — szöveges reprezentáció - Equals(object) — egyenlőség - GetHashCode() — hash kód - GetType() — futásidejű típus

Dinamikus és statikus osztályok

Statikus osztály (static class): - Nem példányosítható (új objektumot nem lehet belőle létrehozni) - Csak static tagokat tartalmazhat - Hasznos: matematikai/segédfüggvények csoportosítására (pl. Math, Console) - Nem örökölhető (implicit sealed)

public static class Math {
    public static double Sqrt(double x) { ... }
}

✚ Pótlás: Dinamikus osztály (dynamic)

A C# erősen típusos nyelv (a fordítás során ellenőrzi a típusokat), de a dynamic kulcsszóval futásidőben is feloldhatjuk a típusellenőrzést.

dynamic típus: a fordító nem ellenőrzi a műveleteket — minden a futás során oldódik fel a DLR (Dynamic Language Runtime)-on keresztül.

dynamic x = "Hello";
x = 5;             // OK — futásban változhat a típus
x.SomeMethod();    // fordításkor OK, futásban dől el

Felhasználása: - COM/Interop — Office automatizálás, ahol a típusok futásban derülnek ki - JSON / XML dinamikus feldolgozása - Reflection alternatívája - IronPython / IronRuby integráció

ExpandoObject: dinamikusan bővíthető objektum — futás közben adhatunk hozzá tulajdonságokat.

dynamic obj = new ExpandoObject();
obj.Nev = "Peti";
obj.Eletkor = 25;

Kockázat: elveszti a fordítóidejű biztonságot, lassabb is a normál típusosnál.

Dinamikus vs statikus típusosság: - Statikus: C#, Java, C++, Rust — a típusok fordításkor rögzítettek - Dinamikus: Python, JavaScript, Ruby — a típusok futás közben oldódnak fel

b) Adatbázisrendszerek I — SQL

SQL nyelv

SQL (Structured Query Language): szabványos lekérdező és manipuláló nyelv relációs adatbázisokhoz. Deklaratív — leírjuk, mit akarunk, nem hogyan.

SQL al-nyelvek: - DDL (Data Definition Language): sémák, táblák — CREATE, ALTER, DROP - DML (Data Manipulation Language): adatok — INSERT, UPDATE, DELETE, SELECT - DCL (Data Control Language): jogosultságok — GRANT, REVOKE - TCL (Transaction Control): COMMIT, ROLLBACK, SAVEPOINT

Relációsémák definiálása

CREATE TABLE Diakok (
    id INT PRIMARY KEY,
    nev VARCHAR(50) NOT NULL,
    szul_ev INT,
    csoport_id INT,
    FOREIGN KEY (csoport_id) REFERENCES Csoportok(id)
);

Megszorítások (constraints): - PRIMARY KEY — elsődleges kulcs - FOREIGN KEY ... REFERENCES — idegen kulcs - NOT NULL — kötelező érték - UNIQUE — egyedi - CHECK (feltétel) — érték-megszorítás - DEFAULT — alapérték

Táblák módosítása (ALTER, DROP)

ALTER TABLE Diakok ADD email VARCHAR(100);
ALTER TABLE Diakok MODIFY nev VARCHAR(80) NOT NULL;
ALTER TABLE Diakok DROP COLUMN email;
DROP TABLE Diakok;

Indexek

Index: különálló adatszerkezet, ami felgyorsítja a keresést egy oszlopon. Tipikusan B-fa vagy B+-fa.

CREATE INDEX idx_nev ON Diakok(nev);
DROP INDEX idx_nev;

Előny: gyors WHERE keresés, JOIN, rendezés. Hátrány: több hely, lassabb INSERT/UPDATE/DELETE (az indexet is karban kell tartani).

A PRIMARY KEY és gyakran a UNIQUE automatikusan indexelt.

SELECT parancs

Alapforma:

SELECT oszlop1, oszlop2
FROM tábla
WHERE feltétel
GROUP BY oszlop
HAVING csoport_feltétel
ORDER BY oszlop [ASC|DESC]
LIMIT n;

Klauzulák sorrendje a végrehajtásban (logikailag): FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.

Aggregáló függvények: COUNT(*), SUM(x), AVG(x), MIN(x), MAX(x).

GROUP BY: csoportosítás. HAVING: szűrés a csoportokon (WHERE az egyedi sorokon).

SELECT varos, COUNT(*) AS db
FROM dolgozok
GROUP BY varos
HAVING COUNT(*) > 10;

DISTINCT: duplikátumok eltávolítása.

Több táblára vonatkozó lekérdezések — JOIN

INNER JOIN: csak azokat a sorokat adja vissza, amelyekre van pár.

SELECT d.nev, c.nev AS csoport
FROM Diakok d
JOIN Csoportok c ON d.csoport_id = c.id;

LEFT JOIN: a bal tábla minden sorát visszaadja; ha nincs pár → NULL. RIGHT JOIN: a jobb tábla minden sorát. FULL JOIN: mindkettő minden sorát; nincs pár → NULL. CROSS JOIN (Descartes-szorzat): minden bal-jobb kombináció. FROM a, b (WHERE nélkül).

Self-join: ugyanaz a tábla aliasszal.

Beágyazott lekérdezések (subquery)

Egy SELECT belsejében másik SELECT.

Skalár subquery: egyetlen értéket ad.

SELECT nev FROM dolgozo WHERE fizetes > (SELECT AVG(fizetes) FROM dolgozo);

IN / NOT IN: halmaz-tagság.

SELECT nev FROM dolgozo WHERE varos IN (SELECT varos FROM kozpont);

EXISTS: van-e legalább egy találat.

SELECT * FROM dolgozo d
WHERE EXISTS (SELECT 1 FROM project p WHERE p.vezet = d.id);

Korrelált subquery: a belső kérdés a külső sor egy oszlopára hivatkozik.

DML — adatkezelés

INSERT INTO Diakok (id, nev, szul_ev) VALUES (1, 'Anna', 2000);
INSERT INTO Diakok VALUES (2, 'Béla', 1999, 5);

UPDATE Diakok SET szul_ev = 2001 WHERE id = 1;

DELETE FROM Diakok WHERE szul_ev < 1990;

Privilégiumok

GRANT és REVOKE: jogosultságok adása és visszavonása.

GRANT SELECT, UPDATE ON Diakok TO test_user;
REVOKE UPDATE ON Diakok FROM test_user;
GRANT ALL PRIVILEGES ON Diakok TO admin_user;

Privilégium fajtái: SELECT, INSERT, UPDATE, DELETE, REFERENCES, ALTER, INDEX, EXECUTE.

WITH GRANT OPTION: a kapott jogot a felhasználó tovább is adhatja.

Szerepkörök (roles)

Jogosultságok csoportja. Felhasználóknak szerepkört rendelünk → öröklik a szerepkör jogait.

CREATE ROLE fejleszto;
GRANT SELECT, UPDATE ON Diakok TO fejleszto;
GRANT fejleszto TO peter;

Előny: ha sok felhasználónak ugyanaz a joga, egy helyen kezelhető.

Tranzakciókezelés — ACID

Tranzakció: logikai egységként kezelt műveletek sorozata. Vagy minden végbemegy, vagy semmi.

ACID tulajdonságok: - Atomicity (atomosság): mindent vagy semmit - Consistency (konzisztencia): az integritási megszorítások a tranzakció előtt és után is teljesülnek - Isolation (elkülönítés): a tranzakciók látszólag egymástól függetlenül futnak - Durability (tartósság): ha COMMIT-olt, többé nem vész el

COMMIT és ROLLBACK

COMMIT: véglegesíti a tranzakció módosításait. A többi felhasználó számára is láthatóvá válik.

ROLLBACK: visszagörgeti a tranzakció módosításait, mintha meg sem történtek volna. COMMIT után már nincs rá lehetőség.

SAVEPOINT: köztes mentési pont — onnantól is lehet rollback.

Implicit COMMIT történik: - DDL utasítás (CREATE, ALTER, DROP) kiadásakor - Felhasználó kilépésekor

Implicit ROLLBACK történik, ha az alkalmazás rendellenesen fejeződik be.
